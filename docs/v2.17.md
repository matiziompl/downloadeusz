# Downloadeusz v2.17

Data: 2026-11-08

## Dodano

- Przełącznik **ReplayGain po imporcie** w panelu Normalizeusza. Włącza lub wyłącza automatyczną współpracę bez edycji `.env` i bez restartu Downloadeusza; działa także przy niedostępnej usłudze.
- Trwałe ustawienie serwera w istniejącej bazie `/spotdl_config/jobs.sqlite3`, wspólne dla wszystkich użytkowników. Zapisane ustawienie ma pierwszeństwo przed `NORMALIZATION_ENABLED`; przed pierwszym zapisem dotychczasowa zmienna pozostaje wartością domyślną. Baza i ustawienie przetrwają odtworzenie kontenera z zachowanym wolumenem.
- Endpoint `PUT /api/normalizer/settings`, przyjmujący wyłącznie pole `enabled` z wartością logiczną. Panel pokazuje postęp, potwierdzenie albo błąd zapisu i chroni przed nadpisaniem nowego ustawienia przez starsze odświeżenie.

## Zmieniono

- Finalizacja pobrań i importów oraz starsza ścieżka bezpośredniego skanu odczytują bieżące ustawienie. Po wyłączeniu oczekujące automatyczne zadania mogą przy kolejnym podjęciu przejść do skanu Navidrome i playlisty bez potwierdzenia ReplayGain.
- Włączenie integracji podczas już rozpoczętego skanu Navidrome powoduje po potwierdzeniu ReplayGain nowy skan. Wcześniejszy skan nie jest uznawany za potwierdzenie odczytu zmienionych tagów.
- README i instrukcja opisują przełącznik, trwałość i pierwszeństwo ustawienia oraz granice jego działania. Przełącznik nie zatrzymuje kontenera Normalizeusza, jego obserwowania biblioteki ani ręcznych operacji i nie usuwa opublikowanych zleceń. Nie zmienia istniejących tagów audio.
- Wersja API, README, etykieta Dockerfile i tag Compose to 2.17. Istniejący graf z 2.16 pozostaje historycznym obrazem kodu, bez nowego przełącznika; README opisuje to ograniczenie.

## Weryfikacja i ograniczenia

- Testy nowego API oraz istniejące testy normalizacji, pipeline i wejścia workera: 68 przeszło. Nowe testy sprawdzają trwałość, pierwszeństwo nad zmienną środowiskową, walidację, błędy odczytu i zapisu, zmianę offline, kontynuację oczekujących pobrań i importów, zachowanie zleceń oraz niezależność operacji ręcznych. Przed implementacją 14 nowych przypadków nie przechodziło z powodu brakującego endpointu i metod zapisu. Dodatkowy test najpierw odtworzył brak ponownego skanu po włączeniu integracji w trakcie zadania, a po poprawce przeszedł.
- Po poprawce ponownie wykonano testy ustawień, finalizacji, trwałego workflow, regresji pipeline, dokumentacji i bazy kolejki: 57 przeszło. Niezależny przegląd zaakceptował zmianę i powtórzył 68 testów backendu oraz 12 testów panelu Normalizeusza.
- Pełny końcowy przebieg backendu `pytest -q -m 'not e2e'` z `SPOTDL_CONFIG_DIR` w katalogu tymczasowym: 506 testów przeszło, 1 pominięto. Pierwszy przebieg miał 504 poprawne testy, 1 pominięty i 1 błąd istniejącego testu organizera z powodu braku praw do `/spotdl_config`; po skierowaniu konfiguracji do katalogu tymczasowego ten test i pełny zestaw przeszły bez zmiany kodu organizera. Przykład Compose w README porównano z plikiem źródłowym, a blok aktualizacji sprawdzono w izolowanej symulacji z atrapą Dockera, zachowując pliki kont, `.env` i dane.
- Składnia JavaScript oraz 32 testy frontendowe przeszły. Pięć nowych testów przełącznika sprawdza zapis offline, błędy, duplikaty, opóźnione odświeżenia, anulowanie żądania po zamknięciu komponentu i semantykę kontrolki. Wszystkie pięć nie przechodziło przed implementacją.
- Nie uruchamiano przeglądarki, Playwrighta, obrazu Docker ani produkcyjnych usług. Detektor UI zgłosił ostrzeżenia dla istniejącego dokumentu HTML; testy kodu nie stanowią wizualnej oceny ani potwierdzenia pełnej zgodności WCAG.
