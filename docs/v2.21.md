# Downloadeusz v2.21

Data: 2026-11-09

## Dodano

- Widżet **Muzyka** po prawej stronie pod kolejką, z zakładkami **Biblioteka**, **Nieuzupełnione** i **Porządkowanie**.
- Indeks rzeczywistych plików muzycznych w `/downloads`, obejmujący również wcześniejszą bibliotekę poza historią importów. Siatka pokazuje okładkę, tytuł, wykonawcę i album. Wyszukiwanie działa po całym indeksie, ignoruje wielkość liter i znaki diakrytyczne; wyniki są stronicowane. Preferencja 2, 3, 4 lub 6 kolumn jest zapamiętywana w przeglądarce, z ograniczeniem na telefonach.
- Lista brakujących i niepotwierdzonych albumów, również automatycznych albumów zastępczych z wcześniejszych importów Soulseeka.
- Edytor jednego utworu z linkiem MusicBrainz do wydania, nagrania lub grupy wydań. Użytkownik jawnie wybiera wydanie i utwór, porównuje metadane i docelową ścieżkę, a następnie zleca zapis przez trwałą kolejkę.
- Lokalna akcja **Nazwij album tytułem piosenki**, zapisująca świadomie zaakceptowany album zastępczy bez potwierdzania wydania MusicBrainz. Decyzja jest zachowywana także w przenośnym znaczniku tagów.
- Zapis metadanych i uporządkowanie wybranej kopii według istniejących reguł beets, z kontrolą niezmienności audio, wersji podglądu, kolizji i dowiązań, kopiami odzyskiwania oraz aktualizacją powiązanych ścieżek. Niedokończone zlecenia dotyczące pliku opóźniają edycję; po niej działa dotychczasowa finalizacja Normalizeusza i Navidrome.

## Zmieniono

- Dotychczasowe porządkowanie beets i akcję porządkowania pobrań Soulseeka przeniesiono z ekranu głównego do widżetu Muzyka. Pasek statusu pozostaje przy formularzu. Zapisane propozycje beets zachowują dotychczasowe działanie w bieżącej lokalizacji pliku.
- README i instrukcja opisują nowy widok, obsługę brakujących albumów i miejsca zapisu indeksu oraz podglądów. Wersję API, README, etykietę Dockerfile i tag Compose zsynchronizowano do 2.21.

## Weryfikacja i ograniczenia

- Pełny końcowy zestaw backendu: **568 testów zaliczonych, 1 pominięty**. API sprawdzano w pamięci przez FastAPI TestClient, a operacje tagów, ścieżek i tożsamości audio na plikach w katalogach tymczasowych. MusicBrainz, okładki sieciowe i Navidrome zastępowano kontrolowanymi odpowiedziami.
- **70 testów frontendu** i kontrola składni JavaScript przeszły. Pokrycie obejmuje okno i zakładki, wyszukiwanie, strony, kolumny, odrzucanie nieaktualnych odpowiedzi, jawny wybór dopasowania, podgląd i zlecanie operacji, blokadę podwójnego wysłania oraz odświeżanie po zakończeniu zadania. Przeniesione kontrolki porządkowania i główny pasek statusu sprawdzono w strukturze HTML.
- Testy nowych funkcji i znalezionych regresji najpierw wykazały brak lub błędne zachowanie, a po poprawkach przeszły. Sprawdzono m.in. zachowanie okładki zapisanej obok przenoszonego pliku, numerowanie wielu płyt zgodne z beets, anulowanie przed publikacją, brak nadpisania istniejącego celu, nieaktualny podgląd, odtworzenie po przerwaniu zapisu i zachowanie kopii po konflikcie. Ręczna akceptacja albumu przetrwa odtworzenie indeksu, a ponowne użycie starej ścieżki nie nadpisuje identyfikatora przeniesionego utworu.
- Przegląd bezpieczeństwa i niezależny przegląd kodu odtworzyły problemy zapisu i integracji; zgłoszone usterki poprawiono i objęto testami. Agent przeglądu zakończył pracę z powodu limitu przed wydaniem końcowej oceny zatwierdzającej; pełną końcową weryfikację testową wykonał agent główny.
- Kontrola HTML potwierdziła pięć dialogów poza formularzami, zrównoważone znaczniki i unikalne identyfikatory. Wyrażenia Alpine sprawdzono składniowo. Statyczny detektor UI zgłosił 39 ostrzeżeń, m.in. o kontraście, obrazach, kartach i nagłówkach; nie zastępuje to audytu dostępności ani oględzin w przeglądarce.
- Przykład Compose w README jest identyczny z plikiem źródłowym, a wersje są zgodne. Sprawdzono kompletny zestaw źródeł do kopiowania; symulacja komend z atrapą Dockera zachowała konta, `.env`, dane i `.git`, zatrzymała aktualizację przed wyłączeniem usługi przy brakującym module oraz nie kopiowała ani nie uruchamiała po błędzie zatrzymania.
- Nie uruchamiano przeglądarki, Playwrighta, produkcyjnych usług ani wdrożenia. Interfejs jest statyczny i nie wymaga osobnego procesu budowania.
