# Downloadeusz v2.9

Data: 2026-11-08

## Dodano

- Przycisk „Zatrzymaj wszystko” obok odświeżania kolejki i ikonę kosza po prawej stronie każdego aktywnego zadania.
- API anulowania pojedynczego zadania i całej kolejki, trwały status „Zatrzymano” oraz ręczne ponowienie z zachowaniem ukończonych utworów i plików.
- Trwałe wstrzymanie automatycznego importu i webhooków po zatrzymaniu całej kolejki; ręczne dodanie lub ponowienie zadania przywraca automatykę.

## Naprawiono

- Zatrzymany downloader jest przerywany wraz z procesami potomnymi również wtedy, gdy nie wypisuje logów. Opóźnione wyniki wykonawcy nie przywracają anulowanego zadania do kolejki.
- Ponowienie i anulowanie są serializowane w bazie kolejki; ponowienie czeka na zwolnienie wykonawcy. Zatrzymane zadanie Normalizeusza nie może zostać powielone przed potwierdzeniem końca pracy zewnętrznej usługi.
- Kolejka pokazuje komunikat błędu programu pobierającego i kod zakończenia zamiast samego ogólnego błędu. Log podaje próbę i czas do ponowienia; jednoznaczne błędy niedostępności filmu nie są automatycznie ponawiane.
- Uzupełniono README i instrukcję o zatrzymywanie, ponawianie i granice anulowania operacji zewnętrznych.

## Ograniczenia

- Bieżąca operacja zapisu beets może dokończyć pracę do punktu kontrolnego. Anulowanie w Downloadeuszu nie przerywa operacji już przyjętych przez zewnętrzne slskd, Normalizeusza ani Navidrome.
- Wskazany link YouTube zwrócił dostępne formaty w próbie `yt-dlp --simulate`; nie pobierano pliku i nie sprawdzano środowiska produkcyjnego. Sam zrzut z ogólnym błędem nie pozwala potwierdzić przyczyny błędu na serwerze.

## Weryfikacja

- Pełny pytest w odizolowanych katalogach tymczasowych: **453 zaliczone, 1 pominięty**. Pominięty test rozpoznawania Chromaprint wymaga niedostępnego lokalnie `fpcalc`. Zestaw obejmuje API w pamięci, trwałe anulowanie, ochronę przed opóźnionym wynikiem i równoczesnym ponowieniem, zakończenie cichego procesu z potomkiem oraz przywracanie pliku po błędzie zapisu beets.
- Frontend: **21 testów Node zaliczonych**, kontrola składni JS i `git diff --check` zakończone powodzeniem. Nie uruchamiano przeglądarki; frontend nie ma osobnego procesu budowania.
